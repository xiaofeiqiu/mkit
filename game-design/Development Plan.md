## 1. 三次交付与固定范围

| 交付 | 玩家能体验到什么 | 必须完成的内容 | 结束位置 |
|---|---|---|---|
| A：首章内部垂直切片 | 就职取哥布林帽子、林缘探索、灵堂救援、Boss、回城成长与自动采集 | Mage的4元素普通技能＋结印火陨石；18装备模板、3宠物、10房间模块、4主线＋2支线、中英、存档 | 守灯偶事件解决，获得海底线索 |
| B：v1首发候选 | 三职业完整构筑，海底、雪山神庙、千年前古城，回到现在 | 15技能、72装备、12宠物、4 Boss、40房间模块、13主线＋8支线；采集Lv1–6 | 救城归来，看见归人桥与名册变化、巴别塔远景 |
| C：九章完整篇 | 登巴别塔、切断四塔供能、阻止军神开启时空之门与无限轮回 | 162装备、27宠物、9 Boss、90房间模块、28主线＋18支线；采集Lv1–10；旧v1存档续玩 | 关闭时空之门，让现在继续，返回晨铃城 |

三个版本都按2:1斜视地图制作，正式可玩内容同时支持English与简体中文。B与C是内容范围，不预先决定后续内容收费或发行方式。

开发必须保持以下规则：

- 每职业拥有4个普通技能和1个怒气终极。暂按完整设计的“两自动槽＋一手动终极槽”实现，槽数是待定项，不改变技能总数。
- 开局在晨铃城被召唤；安全城内五站免费传送，接任务后进入独立副本，战斗结束回城交付。城市由独立素材拼装，每个物件可单独替换、遮挡与碰撞。
- 就职由击败哥布林、取得帽子并交导师完成；先发起始武器，允许零技能开局。
- 装备以永久基础属性判断穿戴，制作只检查材料；装备品质与随机属性保存在实例中。章节仅决定正常探索和材料来源。
- 远征强化使用白、金、紫三级通用卡，临时强化在出征结束后清除。四档装备品质与三档卡牌品质分别配置。
- 猎人、矿工独立升级，在线和离线自动采集常规材料；不靠挂机取得技能石、宠物蛋或Boss专材。
- Boss血量指数增长，输出和显示来自真实数值；继续使用既定曲线作为原型初值。
- 军神为回到爱人身边试图启动无限轮回。玩家阻止首次世界重置，始终是凡人；重玩、读档与离线结算不是剧情轮回。

这不是“写完代码就完成”的工期：八向角色、九套场景、动画修整、UI、音频和真实试玩都占时间。正式外包、全套逐件换装、全语音、多人、移动端和商店审核等待不在该测算内。AI产出的不可用帧仍需返工，不能按生成次数折算完成率。

M5结束前不锁定后续发布日期。M1实测一个八向角色样板、一个普通敌人和一组地图瓦片；M5实测一整章，记录程序、原画/生成、修整、动画、关卡、翻译、验收各自工时。用下式重估M6以后各包：

`后续包工时 = 新素材数量×实测单件中位工时 + 复用修改工时 + 新机制/任务工时 + 文本/音频工时 + 集成验证工时`

日历周数为`剩余工时×1.25÷每周有效小时`。每周只能投入12.5小时，则上述窗口约翻倍；增加协作者时按具体资产包重新分配，不直接把总时间除以人数。未通过验收的阶段继续修复并重估，不靠删去已确认玩法维持日期。

## 4. 实现顺序与阶段验收

与完整设计第20.2节的对应关系：P0对应M0–M1，P1对应M2，P2对应M3–M5，P3对应M6–M10，P4对应M11–M14，P5对应M15–M16。这里把原阶段拆成可跟踪任务，未另设一套游戏范围。

### M0：建立一个属于这款游戏的起点

- 建立`game/whispering_forest/`，以最小模板启动；保留现有demo作为框架回归样例。
- 确定三个内容版本字段：content、balance、story；故事使用Story v3，卡池仍是boon.v2，二者不混用。
- 建立类型前缀ID、资源目录、双语文本解析、设置页语言切换及独立存档路径。一个示例物品从定义进入UI并存读档。
- 跑现有基线检查、记录本机版本和失败项；导出一个空游戏构建，在目标PC上启动。

完成标准：从独立入口进入主城灰盒；同一存档切中英后重启仍保留设置；不会读取或覆盖demo存档。基线测试结果已记录，后续能区分新增问题。

### M1：先证明斜视战斗可读、可控

- 统一逻辑地面与屏幕投影：64×32菱形瓦片、32逻辑单位/格；碰撞、移动、射程、范围和命中都在逻辑地面计算。
- 加八向移动/朝向、脚底锚点、树冠透明、墙前后排序、窄路和拐角。做一个可绕行的高低台样板，不先铺整章。
- Mage自动普攻、锁定/视线检查、闪避、SK09火球；从调试状态授予火球，仅用于内部灰盒。
- 适配五属性和伤害算法；关闭随机闪避率示例；实现普通施放生成前取消不扣MP、不进入完整CD。
- 做3个普通敌人、1个精英的灰盒行为，覆盖近战冲刺、远程弹、范围预警。加入T101教学哥布林流程骨架。
- 量测八向角色/植物/敌人样板工时，制作一屏正式风格候选用于定笔触。

完成标准：玩家能看清将要落在哪里的攻击；狭道中法术、碰撞、宠物预留导航尺度一致；同一招式在四个方向和不同地图位置伤害一致。连续10分钟交战无必然卡死；灰盒评审能指出走位带来的实际收益。

### M2：打一局之后确实能成长

- 先做最短A路线、一个占位Boss与回城结算；打通敌人→掉落→背包→配置→再次出征。
- 技能石收藏与重复库存、L1–L5 Merge、一次教学保底。正式内容表登记全部15技能ID，防止后补职业时改ID或重做存档。
- 实现武器/防具/饰品三槽、基础属性穿戴检查、随机品质与EA；先用G101、G105、G115及一件防具/饰品跑通，再填首章18模板。
- 制作只扣材料；随机结果、craft_id和输入扣除一次提交。制作中断、强化和升阶均保留实例规则。
- 四属性石、魔石出售/逐属性加点/免费重配；不连接demo击杀XP自动升级通路。

完成标准：Q101先领武器、零技能取帽并交导师；Q102教学石只给一次。相同技能换上G115后能观察到弹道变化。没有章节首通旗标但材料/基础属性足够时可制可穿；缺属性可制作但不可穿。掉落和制作立即加入恢复用例，不把事务留到M4才设计。

### M3：做完整的一局构筑

- 完成SK09/10/11/12及SK15：普通MP/CD、终极100怒气/0MP/无固定CD；结印预留、提交、取消、空放按设计执行。
- 怒气按有效命中窗口、击杀、节点清空计入；过滤宠物、派生终极和Boss增援等来源，恢复去重状态。
- 先做B01/B02/B03/B04/B05/B06/B07/B10八类×白金紫三级与3项F补给；同类高档替代、无收益过滤、抽牌暂停、读档恢复原候选。
- 3只首章宠物、1主战槽、蛋/孵化/Merge、跟随、治疗和倒地恢复；不向玩家添加宠物被动属性。
- 分开局内与永久状态；加入料理、技能/装备/宠物详情和大数字反馈。

完成标准：0MP但怒气满可放终极；结印取消不失怒，提交只扣一次。多弹装备＋数量卡不产生指数复制或额外怒气。换宠不改玩家面板；切换技能可继承合法通用卡。选卡中退出不会重抽。

### M4：补齐自动采集和跨系统恢复

- 猎人/矿工各Lv1–2、1线路，8小时货仓；统一在线/离线批次结算、独立经验、升级费用和容量显示。
- 注入可控测试时钟，验证暂停、退出、满仓、负时间、长离线和部分归仓；暂停战斗不暂停现实时间采集。
- 完成profile、run、gathering、story各scope和事务协调；保存随机结果及一次提交标识，明确哪些状态随Boss重试恢复。
- 准备节点/Boss入口/阶段快照；永久掉落和采集不会因为战斗重试回退或复制。

完成标准：Lv1两队30分钟得到H/P/O/C各2，8小时合计128常规材料；在线/离线等时结果一致。归仓、升级、选卡、制作、Boss奖励发生中断后，物品、消耗与旗标账目一致。无需真的等一天测试。

### M5：把第一章做成内部可玩切片

- 完成Q101–Q104、S101–S102，可走主城/5站传送、10房间模块、四战斗节点、A/B/C路线和3种异变。
- 完成6普通敌人、2精英、T101独立教程敌人、B01守灯偶、3宠物、18装备图标与全部参数、2料理。
- 替换正式植物/地表/物件/角色资源，完善预警、受击、伤害字、灯光与声音；法师火陨石有结印、召唤、坠落、火痕分段反馈。
- 中英完成本章所有玩家可见文本；可切语言、跳过已读、回看线索；手柄支持完成一整局。

## 5. 游戏代码与数据组织

以下目录是拟创建结构，不表示已经存在：

```text
game/whispering_forest/
  bootstrap.tscn
  bootstrap.gd
  systems/           # 战斗策略、施放/怒气、制作、宠物、采集、剧情、文本
  data/shared/       # 属性、技能、稀有度、卡、配方规则、文本术语
  data/chapters/     # CH01–CH09内容定义及资源数据库
  scenes/hub/
  scenes/chapters/
  scenes/actors/
  ui/
  localization/
  assets/            # 按共享/章/角色类型分包
  debug/             # 测试时钟、固定种子、合法构筑与状态观察
test/whispering_forest/
  unit/
  integration/
  fixtures/          # 存档、种子、事件序列与版本样本
```

静态资源使用ContentDefinition/ResourceDatabase接入，运行时实例与定义分离。MD是规则来源；M0–M2建立经过审核的结构化内容表到运行资源的单向导入，不用正则在运行时解析MD，也不同时手改两套数值表。

| 边界 | 负责的数据 | 必须避免的混用 |
|---|---|---|
| 永久profile | 属性购买、技能收藏、装备随机实例、宠物、金币/材料 | 从战斗快照覆盖已到账成长 |
| run | 地图seed、临时卡、料理、怒气、节点/阶段状态 | 退出一局后把临时增益保留为永久 |
| gathering | 两队等级、批次、货仓、线路/补货、时钟和余量 | Boss重试让离线进度回退或重新发放 |
| story | era、present_revision、任务/证据、桥/四塔/关门旗标 | 把旅途回响当真实历史再改写 |
| settings | 中英偏好、输入/音量/画面 | 语言切换改任务、掉落或战斗状态 |

每次奖励/制作/Merge/归仓先确定同一个事务的输入、随机结果和输出，再一次持久化；恢复只能应用已记录的结果。存档允许分scope管理，但跨scope动作由同一协调器提交，不能由多个UI各扣一次材料。

`boss.B01`、`material.B01`、`boon.v2.B01.white`必须是不同ID。新增目录内的游戏规则不能让`addons/mkit/`反向依赖章节、NPC、技能编号；不为本游戏新建第二套全局服务容器。

## 6. 素材与内容生产流水线

v0.6 城市已完成用户概念确认后的独立 Blender 模型制作与接入：30 个 Blender 源、48 个三维源模型、168 张方向精灵。布局保留连续门墙、东西桥、公共轴、13栋/9类建筑与44棵规划树木，共198个直接场景对象，可在Godot编辑。新增城内右键绕障寻路。验收须同时看总览与门前/街道近景，并验证所有传送点、建筑门前、门洞与桥的通行；详细规划与图源见[城市重建说明](../game/whispering_forest/art/city/README.md)。服务外观完成不能代替交易、制作、采集或室内场景的实现。

v0.4人物动态样板已建立可编辑关节模型→八向烘焙→透明帧检查→实际地图试玩的流程。3角色×4动作×8方向×8帧共768帧已交付；主城中梅尔以待机/转向接应，未把预备行走资源算成已完成NPC日程。下一步先细修衣服/肢体连接，补专用受击、闪避、倒地、交互与表情，再统一环境笔触；保持原计划所有角色动作验收范围。

正式场景素材采用**三维模型/模块→固定正交相机与共用光照→独立透明素材→地图布置→实机检查**。AI辅助概念、纹理和装饰，几何投影由相机锁定；同样的生成提示词不能作为透视一致性的保证。保留2:1斜视、72px人形身高与64×32地块基准；相机、单位、像素密度、地基/脚底锚点统一，具体标准见[场景素材统一投影标准](<../game/whispering_forest/art/city/Projection Standard.md>)。当前城市主体已用独立三维源与 Blender 修整资产替换，四向来自同一模型旋转；路沿与围栏保留可编辑 Godot 三维源。源文件、像素、锚点与场景引用的技术检查已通过；模型美术仍需按实际观感评估，不将技术通过等同于用户最终审美验收。

地面瓦片、房屋/公会/工坊、城门/墙段、树木/花草、家具和传送石仍各自生产，禁止以一张整城图片代替可走场景。总览截图从引擎渲染；地面坐标、碰撞、门位和Y排序均可独立编辑。明亮度和绿色以用户2026-09-06参考图为准，见TileMap-ref中的新增参考。

顺序：**尺寸/锚点样板 → 灰盒验证 → 一个完整可用角色/环境样板 → 当章最短路线 → Boss与技能反馈 → 内容补齐 → 实机复核。**

| 批次 | 制作内容 | 放行条件 |
|---|---|---|
| A0 样板 | 64×32地块及边角、树/墙遮挡、一名Mage八向动作、一个普通敌人、一个预警圈、两语言UI | 投影一致、脚底不漂、旋转方向清楚、文字不入图 |
| A1 共用 | 六类武器动作规范、三职业轮廓、技能/装备/宠物图标框、白金紫卡框、四元素标识、UI与音效基调 | 确认笔触与装备外显方案；建立可复用命名和导入预设 |
| A2 首章 | 主城五街区/召唤台/传送石、植物/地表、城外与灵堂物件、教程帽子、守灯偶、3宠物、18装备图标、5法师技能VFX | 先完整一条A路线，再补路线变体与装饰 |
| A3 v1 | 海底→雪山→活古城；共用晨铃城与新增NPC | 每章机制灰盒通过后量产；古城与沉港的门位/墙根对齐 |

| A5 终章 | 军神、时空门三态、旧城暮色、关门与归乡演出 | 三阶段与关门状态机先可玩；沿用已确认的感情线结局 |

逐章数量、植物/人物/Boss/宠物与装备清单直接引用Design Full第7–17节。本计划不另造一套资产数量。162模板的四档品质主要靠实例属性与框色表现，不等于制作648张独立装备外观；三路线也不等于三套全新地图。

每个素材任务记录：asset_id、所属章、用途、尺寸、脚底锚点、方向/动作/帧数、透明边界、关联内容ID、来源/使用权限、当前状态、实际工时。状态依次为“待制作→初稿→修整/动画→已导入→实机通过”；生成完成不能直接标为验收完成。

英文和中文不画进共用图标。NPC图、地图和VFX可以共享；牌匾、书页与碑文采用文本层或双语文字层。音频先做战斗预警/命中/稀有拾取/怒气反馈，再做环境与完整音乐；全篇16首音乐按设计逐章交付，首版无全角色双语配音。

## 10. 风险出现时怎样调整

| 可观察的风险 | 触发信号 | 处理方式 |
|---|---|---|
| 八向素材返工太多 | 样板工时明显超预算、动作方向不一致 | 先统一动作模板/轮廓和导入规范；装饰量分批，保留职业和技能规则 |
| 框架默认行为不适配 | 同一招式双扣资源、双算攻击/防御 | 停止扩技能/词条，修复游戏策略入口和集成测试，再继续 |
| 第一章只有数值增长 | 换G115/技能/卡后玩法几乎一样，试玩不愿再打一局 | 调整攻击行为、敌人窗口与卡片反馈；后续素材暂缓量产 |
| 自动采集破坏经济 | 主线需等待、常规材料持续严重积压或补货重复下单 | 依据实际消耗调整批次/配方与补货计数，不加入收费加速或章节装备锁 |
| 穿越/终战状态难恢复 | 桥反复变化、关门重发奖励、重试退回工人经验 | 用提前的两个房间/最终门灰盒定位事务，先修状态再做演出 |
| 神域画面遮住战斗 | 粒子、树冠/柱子、白金背景盖住预警 | 降低装饰干扰，检查图层/透明度/预警边框，保持招式读法 |
| 三职业输出差距扩大 | 同阶合法构筑Boss耗时持续明显偏离目标 | 查实际输出窗口、MP、命中与倍率，再调参数，不只继续抬血 |
| 后期排期失真 | 已完成章实际工时持续高于估算 | 更新剩余工时和交付窗口；优先分期交付已定内容，范围变更单独记录 |

## 11. 开发任务的记录方式

一个任务对应一个可演示结果，通常控制在半天至两个人日；超过三天就拆成“规则/数据→接入→表现→验证”。每个任务记录阶段、前置任务、内容ID、拟修改路径、验收步骤、实际工时和状态。

示例：`M3-RAGE-02 / 火陨石取消与提交`，前置为资源池、施放动作和SK15定义；完成时演示“满怒0MP可启动、结印取消保持100、提交后只扣一次、退出恢复不多发陨石”，并附针对这些边界的测试结果。不能仅以“RageController代码写完”作为完成标准。

每周做一次可玩构建，先查看阻断项与上周承诺的验收，再安排下一周最高依赖任务。原型阶段优先保证战斗、数据和保存的正确性；内容阶段一次完成一个章节包。阶段退出依据实际交付证据，所有未通过项继续留在任务表中。
