Mkit 用户手册（按现有实现）

本文直接对应仓库中 addons/mkit/ 与 game/demo/ 的现有代码。重点是“现在怎么接入、怎么跑通、哪里有硬约束”，不是概念性设计草案。

3. 快速接入（按当前工程）

3.1 启用插件

  • 启用 res://addons/mkit/plugin.cfg。
  • 插件只注册一个 autoload：ServiceRegistry。
  • 其他服务都由 GameBootstrap 创建并写入注册表。

3.2 创建 Bootstrap 场景

[node name="Bootstrap" type="Node"]
script = ExtResource("res://addons/mkit/kernel/bootstrap/game_bootstrap.gd")
initial_scene_path = "res://game/demo/phase3_inventory_slice.tscn"
  • resource_databases: Array[ResourceDatabase]：可选。用于开局批量注册内容。
  • initial_scene_path: String：必填（除非你只想停在 bootstrap 场景）。
保护逻辑已实现：initial_scene_path 不能指向当前 bootstrap 场景本身，否则会被拒绝并报错（防无限重载）。

4. High Level Architecture（代码结构）

Mkit 的高层结构是“game/ 负责内容，addons/mkit/ 负责机制”。运行时通过 GameBootstrap 装配服务，并在 gameplay 场景中由模块节点协作。

4.1 分层结构

层 路径 职责
Game Content Layer res://game/ 玩家/敌人场景、房间场景、demo 驱动脚本、具体数值和内容。
Module Layer res://addons/mkit/modules/ Entity/Stats/Combat/Ability/Inventory/Room/Progression 等可复用领域模块。
Kernel Layer res://addons/mkit/kernel/ Command/HFSM/Action/Effect/Event/Service/Save 等基础运行时。
Platform Adapter Layer res://addons/mkit/kernel/services/*_service*.gd Analytics/Ads/IAP/CloudSave 抽象接口与 mock 实现。

4.2 依赖方向（硬约束）

res://game/*
    -> res://addons/mkit/modules/*
        -> res://addons/mkit/kernel/*

禁止反向依赖：
addons/mkit/* 不能依赖 res://game/*
这条边界保证 Mkit 作为 kit 可复用；项目换内容时不需要改 kit 内核。

4.3 运行时装配

Bootstrap Scene
  -> GameBootstrap.boot()
  -> register services into ServiceRegistry
  -> load/validate content
  -> enter initial_scene_path

服务对象分两类：Node 服务（events/commands/actions/save 等）挂在 ServiceRegistry 下；RefCounted 服务（random/time/effects）以对象形式注册。

5. Gameplay Pipeline（运行管线）

5.1 主管线（实时玩法）

Input / AI / Script
  -> GameCommand
  -> CommandRouter.dispatch
  -> CommandReceiver.receive_command
  -> StateMachine.handle_command / transition
  -> ActionRunner.start_action (optional)
  -> EffectExecutor.execute(_many)
  -> Domain Modules (Combat/Inventory/Room/Progression...)
  -> EventRouter.emit_*
  -> HUD / VFX / Audio / Analytics listeners

5.2 技能与伤害落地管线

CAST_ABILITY command
  -> PlayerCastAbilityState
  -> AbilityController.cast
     -> cost/cooldown/conditions check
     -> CastAction (if cast_time > 0)
     -> execute ability effects
        -> DealDamageEffect / ApplyStatusEffect
        -> CombatResolver.resolve
        -> HealthComponent.apply_damage
        -> EventRouter.damage_applied / entity_died

5.3 Run/Room 管线

RunDirector.start_run
  -> DungeonGenerator.generate_linear
  -> load room scene
  -> RoomController.enter_room + spawn_enemies
  -> EventRouter.entity_died
  -> RoomController.check_clear_condition
  -> RewardSystem.generate_options
  -> RunDirector.select_reward
  -> enter_next_room / complete_run

5.4 Platform 管线（Phase 6）

Gameplay/UI
  -> AnalyticsService / AdService / IAPService / CloudSaveService
  -> Mock adapters (current)
  -> callback signals (completed/failed)
  -> gameplay reward / entitlement / sync feedback

5.5 Component 概念词典（全量）

本节按当前 addons/mkit 的实现覆盖核心组件与类。每项包含三部分：概念、具体使用方式、典型场景。

Kernel：启动与服务

  • ServiceRegistry：概念：全局服务定位器。使用：通过 ServiceRegistry.get_service("events") 读取服务，启动时由 bootstrap 注册。场景：任何跨模块调用（如技能里拿 EffectExecutor）。
  • GameBootstrap：概念：运行时装配器。使用：挂在 bootstrap 场景，设置 resource_databases 和 initial_scene_path，调用 boot()。场景：游戏启动、切换切片场景。
  • RandomService：概念：统一随机源。使用：set_seed()、randf_range()、weighted_pick()。场景：掉落抽卡、房间生成、暴击掷点可复现。
  • TimeService：概念：玩法时间控制器。使用：set_paused()、set_gameplay_time_scale()、get_scaled_delta()。场景：暂停、子弹时间、加速战斗。
  • SceneRouter：概念：场景切换门面。使用：change_scene(path)、reload_current_scene()，监听失败信号。场景：从主菜单进战斗、run 结算后回大厅。
  • ObjectPool：概念：对象复用池。使用：warmup() 预热、acquire() 取对象、release() 归还。场景：频繁生成投射物、伤害数字、特效。
  • SaveManager：概念：本地存档编排器。使用：save_game(root)/load_game(root)，只处理 Saveable。场景：暂停菜单手动存档、开机自动读档。
  • SaveMigration：概念：存档迁移步骤。使用：继承并重写 _migrate_impl，在 SaveManager.migrations 配置版本链。场景：改存档字段后兼容旧玩家数据。
  • Saveable：概念：可存档契约。使用：组件继承它并实现 to_save_data/from_save_data。场景：元进度、经验、任务状态持久化。
  • AnalyticsService：概念：埋点接口。使用：track_event(name, props)、set_user_property()。场景：run_start/room_clear/购买转化统计。
  • AnalyticsServiceMock：概念：埋点 mock。使用：bootstrap 默认注册；调用同 AnalyticsService。场景：无 SDK 时联调埋点行为。
  • AdService：概念：激励广告接口。使用：先 is_rewarded_ad_ready() 再 show_rewarded_ad()，监听 completed/failed。场景：看广告复活、看广告加奖励。
  • AdServiceMock：概念：广告 mock。使用：调用 show 后延迟回调 completed。场景：离线开发期测试广告奖励分支。
  • IAPService：概念：内购接口。使用：load_products()、purchase()、restore_purchases()、is_purchased()。场景：商品页、去广告包、恢复购买。
  • IAPServiceMock：概念：内购 mock。使用：购买后把 product_id 加入本地已购列表。场景：商店 UI 与解锁流程联调。
  • CloudSaveService：概念：云存档接口。使用：save_to_cloud(slot,data)、load_from_cloud(slot)。场景：跨设备同步、云端恢复。
  • CloudSaveServiceMock：概念：云存档 mock。使用：以内存字典模拟 slot，异步回调 load/save。场景：无后端时验证云同步 UX。

Kernel：指令、状态、动作、效果、事件

  • GameCommand：概念：输入意图包。使用：GameCommand.create(type,source,target,payload) 构建。场景：键盘输入、AI 决策、剧情脚本统一进线。
  • BuiltinCommands：概念：命令常量表。使用：发命令时用 BuiltinCommands.ATTACK 等常量。场景：避免 command 字符串拼写漂移。
  • CommandRouter：概念：命令路由总线。使用：实体 ready 时注册 receiver，外部用 dispatch()/broadcast()。场景：玩家输入分发、AI 对多目标发命令。
  • CommandReceiver：概念：实体命令入口。使用：挂在实体根节点，配置 receiver_id，内部把命令转给 StateMachine。场景：玩家、敌人、NPC 的命令落点。
  • StateMachine：概念：分层状态机引擎。使用：场景里配置状态树和 initial_state_path，命令处理里调用 transition_to()。场景：角色 Idle/Move/Attack、Run 子流程状态。
  • State：概念：状态节点基类。使用：继承并重写 enter/exit/update/handle_command。场景：每个具体行为状态实现。
  • Blackboard：概念：状态共享变量表。使用：set_value/get_value 存 movement/facing/目标等临时态。场景：状态间传递方向、缓存目标。
  • GameplayContext：概念：效果与系统调用上下文。使用：from_command() 或手工填 source/target/ability_id/payload。场景：施法、奖励应用、掉落生成。
  • ActionContext：概念：动作上下文。使用：启动 action 时传 ActionContext（direction/duration/payload）。场景：冲刺、施法、近战窗口。
  • GameAction：概念：时序任务抽象。使用：继承后实现 _on_start/_on_update，在合适时机 complete()。场景：前摇后摇动作、蓄力动作。
  • ActionRunner：概念：动作调度器。使用：start_action(action, ctx) 启动，自动每帧 update。场景：多个动作并行执行与统一取消。
  • CastAction：概念：通用施法动作。使用：设置 duration 后交给 runner。场景：有读条/咏唱时间的技能。
  • DashAction：概念：通用冲刺动作。使用：设置 direction/speed/duration，绑定角色 body。场景：位移技能、闪避动作。
  • TimedAttackAction：概念：近战窗口动作。使用：设置 startup/active/recovery 和 hitbox_path。场景：刀剑挥砍、多段近战节奏。
  • Condition：概念：可组合判定规则。使用：继承并实现 _evaluate_impl。场景：技能前置、奖励解锁前置。
  • ConditionEvaluator：概念：条件聚合器。使用：evaluate_all() 或 collect_failures()。场景：给 UI 返回“为什么不能释放/不能选”。
  • TargetInRangeCondition：概念：距离判定条件。使用：配置 range 并附到 ability/effect。场景：近战只能对范围内目标生效。
  • CooldownReadyCondition：概念：冷却判定条件。使用：配置 ability_id 或走 context.ability_id。场景：禁止冷却未完成时重复释放。
  • GameEffect：概念：声明式世界改动单元。使用：子类实现 _apply_impl，外层由 executor 驱动。场景：技能、奖励、物品效果统一执行。
  • EffectResult：概念：效果结果标准结构。使用：返回 ok() 或 fail()，携带 payload。场景：调试链路与 UI 反馈。
  • EffectExecutor：概念：效果执行中枢。使用：execute()/execute_many()，可 stop_on_failure。场景：技能组合效果、奖励连锁效果。
  • LogEffect：概念：调试效果。使用：设置 message/event_type 后执行。场景：验证状态机到效果链路是否通。
  • DealDamageEffect：概念：效果层伤害桥接器。使用：配置 base_amount/damage_type/on_hit_statuses。场景：法术命中伤害、持续伤害 tick。
  • HealEffect：概念：治疗效果。使用：配置 base_amount，target 为空时回退到 source。场景：药水、治疗技能、奖励回血。
  • ApplyStatusEffect：概念：状态施加效果。使用：配置 status_id/stacks/duration_override。场景：火球附燃烧、中毒、减速。
  • GrantItemEffect：概念：物品发放效果。使用：配置 item_id/quantity，选 source 或 target 背包。场景：奖励选项发装备、任务发道具。
  • ApplyStatModifierEffect：概念：数值增益效果。使用：配置 stat/op/value/duration，注入 StatsComponent。场景：天赋增益、临时 BUFF。
  • SpawnSceneEffect：概念：场景生成效果。使用：配置 scene_path，按 source/target 定位实例。场景：投射物、召唤物、AOE 特效。
  • DomainEvent：概念：已发生事实对象。使用：DomainEvent.create() 构造并交给 EventRouter。场景：日志、回放、debug 事件时间线。
  • EventRouter：概念：领域事件总线。使用：监听 damage_applied/entity_died/... 或调用 emit_*。场景：HUD、音效、动画、统计解耦联动。
  • DebugOverlay：概念：调试视图层。使用：设置 watch_entity_path，运行时 toggle()。场景：实时看状态路径、最近事件、最后命令。
  • ResourceDatabase：概念：内容打包资源。使用：在资源里填 resources/resource_paths，bootstrap 加载。场景：分包管理能力、道具、房间定义。
  • ContentRegistry：概念：内容查找中心。使用：register_resource()/get_resource(id)/validate_all()。场景：运行时按 ID 取技能/房间/奖励定义。
  • ContentValidationResult：概念：内容校验报告。使用：检查 success/errors/warnings。场景：启动校验失败时阻断上线。

Modules：Entity / Stats / Health / Combat

  • EntityRoot：概念：实体根模板。使用：角色场景根节点继承它，便捷调用 get_component/get_controller。场景：玩家和敌人共用统一组件路径。
  • EntityIdentity：概念：实体身份卡。使用：挂节点并填 entity_id/faction/tags。场景：阵营判定、命令路由、事件归因。
  • EntityDefinition：概念：实体资源模板。使用：配置 scene_path、base_stats、starting_ability_ids。场景：按定义刷怪、按关卡切换怪物模板。
  • EntitySpawner：概念：实体工厂。使用：spawn_entity(definition_id,parent,pos)。场景：房间进入时批量刷敌人。
  • StatDefinition：概念：单项属性元定义。使用：配置 stat_id/default/min/max。场景：策划定义属性字典。
  • StatModifierDefinition：概念：属性修饰模板。使用：配置 operation/value/stacking_rule。场景：装备词条、buff、奖励增益。
  • StatModifier：概念：运行时修饰实例。使用：由 from_definition() 生成，带 source 与 duration。场景：限时加攻、来源可追踪回收。
  • StatsComponent：概念：属性计算核心。使用：挂在 Components/StatsComponent，调用 get_stat_value/add_modifier。场景：伤害公式、移动速度、冷却缩减读取。
  • ResourcePoolComponent：概念：资源池（mana/stamina）。使用：配置 starting_values，用 spend/restore。场景：施法扣蓝、冲刺扣体力。
  • HealthComponent：概念：生命系统节点。使用：调用 apply_damage/heal/die/revive。场景：战斗伤害落地、死亡事件广播。
  • DamageRequest：概念：伤害输入结构。使用：填 source/target/base_amount/tags 后交给 resolver。场景：hitbox 命中、技能效果命中。
  • DamageResult：概念：伤害输出结构。使用：读取 final_amount/critical/lethal/trace。场景：伤害飘字、战斗日志、调试。
  • CombatResolver：概念：伤害规则执行器。使用：resolve(request) 返回 result。场景：统一近战和技能伤害公式。
  • HitboxComponent：概念：攻击判定体。使用：攻击窗口里 set_active(true)，配置 target_factions/base_damage。场景：普攻挥砍、近战技能。
  • HurtboxComponent：概念：受击判定体。使用：挂在目标并配置 owner_path/can_receive_damage。场景：玩家受击盒、敌人受击盒。

Modules：Ability / Status

  • AbilityDefinition：概念：技能模板资源。使用：配置 cost/cooldown/cast_time/conditions/effects。场景：火球、冲刺、治疗等技能数据化。
  • AbilityInstance：概念：技能运行态。使用：由 AbilityController 注册后自动维护 cooldown/charges。场景：同一技能在不同角色上独立冷却。
  • AbilityController：概念：技能执行入口。使用：register_ability() + cast()。场景：玩家按键施法、AI 自动施法。
  • StatusEffectDefinition：概念：状态模板资源。使用：配置 duration/tick_interval/stack_rule/effects_on_*。场景：燃烧、中毒、护盾、减速。
  • StatusEffectInstance：概念：状态运行实例。使用：由 controller.apply_status 创建并维护剩余时间与层数。场景：每个目标单独追踪状态持续。
  • StatusEffectController：概念：状态生命周期管理器。使用：apply_status/remove_status/has_status。场景：命中附加状态、到期移除状态。

Modules：Inventory / Loot / Reward

  • ItemDefinition：概念：物品模板资源。使用：配置 stackable/equipment_slot/use_effects/stat_modifiers。场景：武器、消耗品、材料等定义。
  • ItemInstance：概念：物品实例。使用：ItemInstance.create() 生成并带 instance_id。场景：同类物品不同数量/耐久/词缀。
  • InventorySlot：概念：背包单格。使用：通过 model.slots 管理，空位用 is_empty() 判断。场景：UI 格子映射。
  • InventoryModel：概念：背包纯数据层。使用：setup(capacity)、查空槽/可堆槽。场景：与 UI/网络层分离存储模型。
  • InventoryController：概念：背包行为层。使用：add_item/remove_item/find_item，事件通知。场景：拾取掉落、消耗物品、存读档。
  • EquipmentController：概念：装备行为层。使用：equip/unequip/get_equipped 并自动应用属性。场景：穿戴武器护甲、切换装备。
  • LootEntry：概念：单条掉落规则。使用：配置 content_id/weight/quantity/conditions。场景：敌人不同权重掉不同道具。
  • LootTableDefinition：概念：掉落表资源。使用：配置 rolls、allow_empty、entries。场景：普通怪/Boss/chest 各自掉落池。
  • LootRollResult：概念：掉落结果对象。使用：读取 item_instances 和 debug_rolls。场景：战斗结算展示掉落明细。
  • LootSystem：概念：掉落引擎。使用：roll_table(table_id, ctx)。场景：敌人死亡后按表掷点出货。
  • RewardDefinition：概念：奖励模板资源。使用：配置 display/rarity/weight/effects。场景：清房后三选一奖励池。
  • RewardOption：概念：奖励候选运行对象。使用：RewardSystem 生成后给 UI 展示。场景：玩家在奖励面板点击选择。
  • RewardSystem：概念：奖励流程引擎。使用：generate_options() + apply_selected()。场景：roguelite 每房奖励选择。

Modules：Room / Run / Generation

  • RoomDefinition：概念：房间模板资源。使用：配置 scene_path、enemy_spawn_ids、reward_pool_ids。场景：按房间类型切不同战斗布局。
  • RoomNode：概念：房间图节点。使用：记录 room_definition_id 与 next/previous。场景：分支地图、线性地图拓扑表达。
  • RoomGraph：概念：房间图容器。使用：保存 nodes/start_node/boss_node，按 index 取节点。场景：run 全局房间序列索引。
  • RoomRuntime：概念：房间运行态。使用：进入房间时 create，维护 active_enemy_ids/reward_options。场景：判定“清房了吗”“奖励已生成了吗”。
  • RoomController：概念：房间内流程控制器。使用：setup() 后 enter_room()，监听 entity_died 检测 clear。场景：一间房内刷怪→战斗→奖励完整闭环。
  • DungeonGenerator：概念：地图生成器。使用：generate_linear(pool,seed,length)。场景：seed 固定复现同一 run 地图。
  • RunState：概念：run 全局状态快照。使用：记录 current_room_index/history/reward_history/status。场景：运行中进度追踪与存档。
  • RunDirector：概念：run 编排器。使用：start_run() 启动，select_reward() 推进。场景：roguelite 主循环控制。

Modules：Progression / Experience

  • ExperienceCurve：概念：等级经验曲线。使用：配置阈值数组或 base+growth。场景：角色等级成长平衡。
  • ExperienceComponent：概念：经验与升级组件。使用：挂节点后调用 add_xp()，监听 level_up。场景：击杀加经验、升级特效触发。
  • UpgradeDefinition：概念：元升级模板。使用：配置 cost_by_level/prerequisite/effects。场景：局外天赋树、长期成长。
  • ProgressionState：概念：元进度数据体。使用：保存 currencies/upgrade_levels/unlocked_content_ids。场景：跨 run 持久化元货币与解锁。
  • ProgressionSystem：概念：元进度服务。使用：add_currency()、unlock_or_level_up()、可存档。场景：结算发币、商店购买天赋。

8. Runtime Kernel

8.1 Command

GameCommand.create(type, source, target, payload) 生成命令。CommandRouter.dispatch() 要求 target_id 非空且有注册 receiver。

内置命令常量：move、stop_move、attack、cast_ability、dash、interact、select_reward、equip_item 等。

8.2 HFSM

  • StateMachine.transition_to(path) 使用 LCA 切换（先出后进）。
  • 每帧调用 update 与 physics_update 状态链。
  • handle_command 从当前叶子向父级冒泡。
在状态 enter() 内再次切状态时，若和外层 transition 冲突，需用 call_deferred（demo 的 PlayerCastAbilityState 已处理这个问题）。

8.3 Action

  • ActionRunner 统一驱动 action；受 TimeService 缩放影响。
  • 现有动作：DemoWaitAction、TimedAttackAction、CastAction、DashAction。

8.4 Effect + Condition

  • GameEffect.apply() 先跑 conditions，失败返回 EffectResult.fail。
  • EffectExecutor.execute_many(..., stop_on_failure) 可失败即停。
  • 内置条件：TargetInRangeCondition、CooldownReadyCondition。
  • 内置效果：DealDamageEffect、HealEffect、ApplyStatusEffect、GrantItemEffect、ApplyStatModifierEffect、SpawnSceneEffect、LogEffect。

8.5 EventRouter

核心信号：damage_applied、entity_died、inventory_changed、room_cleared、reward_selected、run_started、run_finished、domain_event_emitted。

9. Entity / Stats / Health / Combat

9.1 Entity

  • EntityIdentity：entity_id / definition_id / faction / tags。
  • EntityDefinition：entity_definition_id、scene_path、base_stats、starting_ability_ids。
  • EntitySpawner.spawn_entity(def_id, parent, pos, runtime_id)：实例化并初始化 identity/stats/abilities。

9.2 Stats

  • StatsComponent 支持 FLAT_ADD / PERCENT_ADD / PERCENT_MULTIPLY / OVERRIDE / clamp。
  • 可叠加规则：STACK、REPLACE_SAME_SOURCE、UNIQUE（HIGHEST_ONLY/LOWEST_ONLY 枚举存在，但当前未实现行为）。

9.3 Combat

  • HitboxComponent 在 set_active(true) 时清空 already_hit 并主动扫描重叠，避免“站桩重叠漏判”。
  • CombatResolver.resolve() 默认公式： (base + attack_power) * damage_multiplier * crit - defense。
  • HealthComponent.apply_damage() 是统一伤害落地入口，会发 damage_applied / entity_died 事件。

10. Ability / Status Effects

10.1 AbilityDefinition

关键字段：ability_id、cooldown、charges、cost_type、cost_amount、cast_time、conditions、effects。

10.2 AbilityController

  • register_ability(id) 后才能 cast。
  • cast(id, context) 流程：校验 → 扣资源 → cast action/直接效果 → 开 CD。
  • CD 读取角色 cooldown_reduction。

10.3 StatusEffectDefinition

支持 effects_on_apply / effects_on_tick / effects_on_remove 与 stat_modifiers。

叠层规则：REFRESH_DURATION / ADD_STACK / REPLACE / IGNORE / EXTEND_DURATION。

11. Inventory / Equipment / Loot / Reward

11.1 Inventory

  • InventoryController 负责堆叠与空位分配，发 inventory_changed 事件。
  • ItemDefinition 可配置 stackable、max_stack、equipment_slot、use_effects。

11.2 Equipment

  • EquipmentController.equip(item, slot_id) 会把 ItemDefinition.stat_modifiers 与 ItemInstance.rolled_affixes 应用到 Stats。
  • unequip 使用 remove_modifiers_from_source(item.instance_id) 回滚。

11.3 Loot + Reward

  • LootSystem.roll_table(id, ctx) 支持空掉落权重与数量区间。
  • RewardSystem.generate_options(pool_ids, count, ctx) 为“给定 reward_id 列表”做加权抽取。
  • RewardSystem.apply_selected(option, ctx) 执行 option.effects，并触发 reward_selected。

12. Room / Run / Generation

12.1 RoomController

  • setup(room_definition_id) 初始化 RoomRuntime。
  • enter_room() → spawn_enemies()。
  • 监听 entity_died，当 active_enemies 为空时触发 room_cleared + 生成奖励。

12.2 RunDirector

  • start_run(seed)：建 run_state、seed 随机服务、生成房间图、进入第一房。
  • select_reward(option)：应用奖励后推进到下一个房间。
  • 玩家死亡判定：事件 entity_died 的 id 等于导出字段 player_entity_id。

12.3 DungeonGenerator

当前仅实现 generate_linear(room_pool_ids, seed, length)：可重复的线性地图。

13. Save / Progression / Experience / Platform

13.1 SaveManager

  • 默认存档文件：user://save.json。
  • 保存入口：save_game(get_tree().root)。
  • 只会序列化 Saveable 子类节点。
data = {
  "save_version": 1,
  "game_version": "0.1.0",
  "timestamp": "...",
  "profile_id": "profile_001",
  "payload": { save_id: save_data, ... }
}

13.2 当前可直接保存的系统

  • ProgressionSystem（服务 progression，继承 Saveable）。
  • ExperienceComponent（demo 动态挂载，继承 Saveable）。
背包、RunState、ResourcePool 当前未直接继承 Saveable。若要持久化，需要包一层 Saveable 节点或改组件继承关系。

13.3 Progression

  • ProgressionState：currencies、upgrade_levels、unlocked_content_ids。
  • unlock_or_level_up(upgrade_id, ctx)：校验前置与成本，通过后执行升级 effects。

13.4 Experience

  • ExperienceCurve 支持手工阈值或公式 base_xp * growth_factor^(level-1)。
  • ExperienceComponent.add_xp() 会循环升级并发 level_up 信号。

15. 常见问题与定位

症状 优先检查 对应代码点
命令不生效 target_id 是否为空；receiver 是否注册；CommandReceiver.receiver_id 是否匹配。 kernel/commands/command_router.gd
状态机不切换 state path 是否正确；是否在 enter() 中同步重入切换。 kernel/state_machine/state_machine.gd
技能释放失败 ability 是否注册；资源是否足够；CD 是否结束；条件是否满足。 modules/abilities/ability_controller.gd
内容注册失败 是否有稳定 ID 字段；是否重复 ID。 kernel/registry/content_registry.gd
刷怪失败 Room 场景是否有 RoomController + EntitySpawner + Enemies。 modules/room/room_controller.gd
存档没生效 对象是否继承 Saveable 并在场景树里。 kernel/save/save_manager.gd

ContentRegistry 能自动识别的稳定 ID 字段名

item_id
ability_id
status_id
room_id
upgrade_id
entity_definition_id
enemy_id
loot_table_id
reward_id
stat_id
自定义 Resource 若不包含以上字段之一，将被判定为“缺少 stable content id”。
